⚡ LO QUE FUNCIONA AUTOMÁTICAMENTE
════════════════════════════════════════════════════════════════════════════

CADA 5 SEGUNDOS
  → AP Vigilante verifica si JETSON_AP está UP
  → Si NO está: lo RECREA INMEDIATAMENTE
  → Si está: no hace nada (muy eficiente)

CADA 10 SEGUNDOS
  → Maximiza potencia TX a 30 dBm
  → Verifica que wlan0 esté en máxima potencia

CADA 30 SEGUNDOS
  → Monitorea SNR (relación señal-ruido)
  → Detecta degradación de calidad

CADA 60 SEGUNDOS
  → Busca el canal WiFi menos congestionado
  → Cambia automáticamente si hay interferencia

CONSTANTEMENTE
  → Diagnóstico rastrea caídas BLE/WiFi
  → Mide tiempo de recuperación
  → Evalúa salud general (buena/degradada/pobre/crítica)
  → Torque se adapta según:
     • Terreno plano → aumenta potencia
     • Pendiente detectada → reduce potencia (seguridad)
     • Motor caliente → throttle automático
  → WiFi gestiona modos (estación/patrullaje)

🚀 CÓMO USARLO
════════════════════════════════════════════════════════════════════════════

PASO 1: Reiniciar el servidor
  systemctl restart agrobot-jetson

PASO 2: Verificar logs (debe mostrar [AUTO])
  journalctl -u agrobot-jetson -f | grep AUTO

PASO 3: Ver estado de comunicación
  curl http://localhost:8000/api/comunicacion/estado | jq

PASO 4: Ejecutar monitor en vivo (opcional)
  python3 tools/diagnostico_wifi_rt.py

PASO 5: Cambiar modo WiFi si es necesario
  curl -X POST http://localhost:8000/api/wifi/modo \
    -H "Content-Type: application/json" \
    -d '{"modo":"estacion"}'  # o "patrullaje"


📈 MÉTRICAS QUE PUEDES MONITOREAR
════════════════════════════════════════════════════════════════════════════

curl http://localhost:8000/api/comunicacion/estado | jq

Muestra:
  • ap_vigilante: caídas, recreos, éxitos
  • comunicacion: potencia, canal, latencia
  • diagnostico: caídas BLE/WiFi, salud
  • torque: parámetros adaptados actuales
  • wifi: modo actual, conectado


🎮 USAR EN DASHBOARD
════════════════════════════════════════════════════════════════════════════

Si tienes un dashboard web que consume /api/*, ya funciona:

JavaScript:
  fetch('/api/comunicacion/estado')
    .then(r => r.json())
    .then(data => console.log(data))

Mostrar salud WiFi:
  GET /api/diagnostico/wifi
  Campo "salud": buena / degradada / pobre / crítica

Cambiar modo:
  POST /api/wifi/modo
  Body: {"modo": "estacion"} o {"modo": "patrullaje"}

⚠️ TROUBLESHOOTING RÁPIDO
════════════════════════════════════════════════════════════════════════════

Problema: "AP sigue cayendo"
Solución: Ejecutar diagnóstico
  python3 tools/diagnostico_wifi_rt.py
  Ver patrón: ¿BLE solo? ¿WiFi solo? ¿Simultánea?

Problema: "No veo [AUTO] en logs"
Solución: Verificar import se agregó
  grep "auto_comunicacion" jetson_server.py

Problema: "Módulos no importan"
Solución: Verificar que están en backend/
  ls backend/auto_comunicacion.py
  ls backend/ap_vigilante.py
  etc.

Problema: "Endpints HTTP no funcionan"
Solución: Verificar que servidor está arriba
  systemctl status agrobot-jetson
  curl http://localhost:8000/api/salud
